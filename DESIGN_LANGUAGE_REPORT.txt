1. DESIGN LANGUAGE OVERVIEW
================================================================================

NAME: "The Tactile Architect" (from DESIGN.md)
PHILOSOPHY: High-end editorial print meets functional utility.
AESTHETIC: Curated, warm, premium — NOT generic Material/SaaS.

FIVE PILLARS OF THE DESIGN LANGUAGE:
─────────────────────────────────────

  1. TONAL LAYERING (No-Line Rule)
     Boundaries are defined by background color shifts, not borders.
     UI elements sit on layered "sheets of fine paper" with subtle tonal
     differences creating depth without explicit dividers.

  2. KINETIC ORANGE
     The brand accent (#FF5E00) is treated as a "laser tool" — used
     sparingly for CTAs, active states, and high-attention elements.
     Never used as a filler. When orange appears, it demands action.

  3. EDITORIAL TYPOGRAPHY
     Clash Display / Epilogue for headlines creates a "magazine" authority.
     Manrope / DM Sans for body provides clean utility readability.
     Heavy use of uppercase tracking-widest labels gives an "archive" feel.

  4. GLASSMORPHISM
     Floating elements (bottom nav, headers) use semi-transparent backgrounds
     (80% opacity) with backdrop-blur to create a "hovering glass" effect.

  5. TACTILE SOFTNESS
     Universal 20px (1.25rem) corner radius. Everything feels "rounded and
     touchable." Combined with subtle shadows, the UI feels physical.

3. TYPOGRAPHY SYSTEM
================================================================================

FOUR FONT FAMILIES USED ACROSS SCREENS:
────────────────────────────────────────

  1. CLASH DISPLAY  (Settings header, Profile section headers)
     - Weight: 600-700
     - Used for: Brand mark ("GAS.UI"), section headers
     - Feel: Brutalist, authoritative, "signature" weight
     - Import: Google Fonts

  2. EPILOGUE  (Headlines in History, Leaderboard, bottom nav labels)
     - Weight: 400-900
     - Used for: Large headlines, stat numbers, nav labels
     - Feel: Geometric, bold, editorial
     - Dominant in: Community screens

  3. MANROPE  (Body text, Analyze, Map, Station Details)
     - Weight: 400-800
     - Used for: Body text, form labels, prices, descriptions
     - Feel: Geometric sans, highly legible, modern
     - Most used font overall

  4. DM SANS  (Camera screen body, Profile body text)
     - Weight: 400-700
     - Used for: Functional text, captions
     - Feel: Slightly softer than Manrope

TYPOGRAPHY HIERARCHY:
─────────────────────
  Display/Hero:     32-48px, Epilogue 900/Black, tracking-tight (-2%)
  Headline H1:      24-30px, Clash Display 700/Bold, tracking-tight
  Headline H2:      20-24px, Epilogue 800/Bold
  Title:            18-20px, Manrope 700/Bold
  Body Large:       16px, Manrope/DM Sans 500/Medium
  Body:             14px, Manrope 400/Regular
  Label:            10-12px, Manrope/Epilogue 700-900, UPPERCASE,
                    tracking-widest (0.2em), sometimes all-caps

LABEL TREATMENT (Distinctive Pattern):
──────────────────────────────────────
  Throughout the app, category labels use a distinctive "archive" style:
  - ALL UPPERCASE
  - Extra-bold weight (700-900)
  - Extremely wide letter-spacing (tracking-widest / 0.2em)
  - Very small size (10px)
  - Muted color (on-surface-variant)

  Examples: "TOTAL CONTRIBUTIONS", "PRICE REPORTED", "POINTS EARNED",
           "YOUR STANDING", "LIFETIME POINTS", "SESSION ID: FT-8829-PX"

  This creates a "utility/archive" aesthetic — like a technical instrument
  readout or high-end print magazine labeling.

4. SPACING & LAYOUT PATTERNS
================================================================================

SPACING SCALE:
──────────────
  xs:    4px   (icon gaps, subtle offsets)
  sm:    8px   (tight element margins)
  md:    12-16px (standard padding, row gaps)
  lg:    24px  (section padding, card padding)
  xl:    32px  (section separation)
  2xl:   48px  (major section breaks)

LAYOUT PATTERNS OBSERVED:
─────────────────────────

  1. FULL-BLEED SECTIONS
     Map View and Camera are edge-to-edge, filling the entire viewport.
     UI overlays float on top with absolute positioning.

  2. CONTAINED CARDS
     History, Leaderboard, Profile, Settings use max-width containers
     (max-w-md or max-w-screen-xl) with horizontal padding (px-6).

  3. BENTO GRID
     History summary and Leaderboard podium use asymmetric grid layouts
     (md:grid-cols-3) where items have different visual weights.

  4. BOTTOM SHEET
     Station Details uses a rounded-top sheet that slides up from bottom,
     with a drag handle for mobile and a side panel for tablets.

  5. SPLIT VIEW
     Analyze & Preview uses a 40/60 vertical split (mobile) or
     50/50 horizontal split (tablet) between image and form.

CORNER RADIUS SYSTEM:
─────────────────────
  Small items (badges, tags):     4-8px (rounded)
  Medium items (inputs, rows):    12-16px (rounded-[16px])
  Large items (cards, sheets):    20px (rounded-[20px], rounded-2xl)
  Pill shapes (buttons, toggles): 9999px (rounded-full)
  Top sheet (bottom sheets):      20px top-only (rounded-t-[20px])

  Rule: Everything uses 20px or pill. No sharp corners anywhere.

RESPONSIVE BREAKPOINTS:
───────────────────────
  Mobile:  < 768px  (single column, bottom sheet, stacked layout)
  Tablet:  >= 768px (side panels, split views, multi-column grids)

  The mockups extensively use `md:` breakpoint for tablet adaptations:
  - Map → Station Details becomes side panel instead of bottom sheet
  - Analyze → image left 50%, form right 50%
  - History/Leaderboard → 3-column bento grid

6. ANIMATION & MOTION LANGUAGE
================================================================================

ANIMATION DENSITY PER SCREEN (lines containing animation/transition/hover):
───────────────────────────────────────────────────────────────────────────
  Settings:           24 lines  (toggles, hover states, scale feedback)
  Map View:           23 lines  (marker hover, FAB press, nav interactions)
  History:            23 lines  (list hover, nav, CTA hover)
  Analyze:            22 lines  (scan animation, focus states, button press)
  Leaderboard:        19 lines  (hover, trend arrows, nav)
  Camera:             14 lines  (shutter press, close button, flash toggle)
  Profile:            14 lines  (button press, nav, progress)
  Station Details:     7 lines  (sheet transform, button press, hover)

MOTION PATTERNS USED:
─────────────────────

  1. PRESS FEEDBACK (universal)
     Every interactive element has `active:scale-95` or `active:scale-[0.98]`
     This gives a "physical button press" feel across the entire app.
     Duration: 100ms (fast, snappy feedback)

  2. HOVER SCALE (map markers)
     Map markers use `hover:scale-110` with `origin-bottom` for a
     "popping up from the map" effect. Transition-transform driven.

  3. SCAN LINE ANIMATION (camera, analyze)
     @keyframes scan: translateY(-100%) → translateY(100%) → translateY(-100%)
     Duration: 3s, ease-in-out, infinite
     Creates the "AI is scanning" visual feedback.

  4. PULSE (user location)
     Blue location dot uses `animate-pulse` (Tailwind built-in)
     to draw attention to user position on map.

  5. BACKGROUND TRANSITIONS (list items, settings)
     hover:bg-surface-container-high for list items
     focus-within:bg-primary/5 for form inputs
     Smooth transition-colors for state changes.

  6. SHEET TRANSITION (station details)
     transform: transition-transform, duration-300, ease-in-out
     Bottom sheet slides up/down for expand/collapse.

  7. GROUP HOVER (history items)
     Using Tailwind `group` + `group-hover:text-primary` to change
     title color when hovering over the parent card.

  8. ICON SCALE (settings)
     Settings list item icons use `group-hover:scale-110` for subtle
     "breathing" feedback on hover.

MOTION PRINCIPLES:
──────────────────
  • All animations < 300ms (fast, responsive feel)
  • Active/press feedback is UNIVERSAL — every button, link, card
  • Hover effects are subtle (color shift or small scale)
  • Only ONE looping animation exists (scan line) — everything else is triggered
  • No page transitions defined in CSS (navigation is instant)

7. SURFACE & ELEVATION SYSTEM
================================================================================

THE LAYERING STACK (bottom to top):
────────────────────────────────────

  Layer 0: MAP / CAMERA FEED (full-bleed background)
  Layer 1: Surface (#F9F9F7) — main content area
  Layer 2: Surface Container Low (#F4F4F2) — card backgrounds
  Layer 3: Surface Container (#EEEEEC) — grouped sections
  Layer 4: Surface Container Lowest (#FFFFFF) — elevated cards
  Layer 5: Floating UI — bottom nav, headers (glassmorphism)
  Layer 6: Overlays — modals, sheets (with backdrop dimming)

SHADOW USAGE:
─────────────
  Whisper Shadow:   0px 24px 48px rgba(26,28,27,0.06)  — floating cards
  Sheet Shadow:     0 -4px 20px rgba(0,0,0,0.1)         — bottom sheets
  Nav Shadow:       0px -24px 48px rgba(26,28,27,0.06)  — bottom navigation
  Marker Shadow:    0 4px 12px rgba(0,0,0,0.15)          — map markers
  Button Shadow:    shadow-lg shadow-primary/20-30        — CTA buttons

  KEY RULE: Only top-most floating elements get shadows.
  Cards within the main content area do NOT use drop shadows — they
  rely on tonal contrast (white card on off-white background).

GLASSMORPHISM PATTERN:
──────────────────────
  Elements using glass effect:
  - Bottom navigation:  bg-white/80 backdrop-blur-md
  - Map search bar:     bg-white/85 backdrop-blur-md
  - Camera header:      bg-black/40 backdrop-blur-md
  - Camera buttons:     bg-surface/20 backdrop-blur-md
  - History header:     bg-surface/80 backdrop-blur-md
  - Helper text pill:   bg-on-surface/40 backdrop-blur-lg

  Glass elements combine 3 properties:
    1. Semi-transparent background (60-85% opacity)
    2. backdrop-blur (blur-md = 12px, blur-lg = 16px)
    3. Subtle border (border-white/50 or none)

10. DESIGN CONSISTENCY ISSUES
================================================================================

ISSUES FOUND ACROSS SCREENS:
─────────────────────────────

  1. PRIMARY COLOR MISMATCH:
     - Map/Analyze/Station: #f95f06
     - Camera/Settings (primary): #a63b00
     - Camera/Settings (container): #ff5e00
     - History/Leaderboard: #FF5E00
     - Profile: #FF5E00
     RECOMMENDATION: Standardize to #FF5E00 (container) + #A63B00 (primary)

  2. FONT FAMILY INCONSISTENCY:
     - History/Leaderboard headlines use Epilogue
     - Settings headlines use Clash Display
     - Map/Analyze/Station use Manrope for everything
     - Profile uses a mix (Clash Display heads, DM Sans body)
     RECOMMENDATION: Unify to Clash Display (headlines) + Manrope (body)

  3. BOTTOM NAV VARIATIONS:
     - Map/Analyze/Station: 4 items (Map, Contribute, Profile, Settings)
     - History/Leaderboard: 4 items (Map, Contribute, Community, Settings)
     - Item labels and icons differ slightly between screens
     RECOMMENDATION: Standardize to Map | Contribute | Community | Settings

  4. BORDER RADIUS DIFFERENCES:
     - Map/Analyze/Station config: 0.25rem DEFAULT
     - Camera/Settings config: 1rem DEFAULT
     - History/Leaderboard config: 1.25rem DEFAULT
     RECOMMENDATION: Use 1.25rem (20px) as universal DEFAULT

  5. HEADER STYLE VARIATIONS:
     - Map: No header (floating search bar)
     - Camera: Floating overlay header with brand
     - History/Leaderboard: Sticky blur header + segmented control
     - Settings: Sticky simple header with brand mark
     - Profile: Sticky header with centered title
     RECOMMENDATION: Acceptable — context-specific headers make sense

11. ACCESSIBILITY AUDIT (FROM PRD REQUIREMENTS)
================================================================================

The PRD mandates WCAG 2.1 AA compliance. Current mockup status:

  ✅ GOOD:
  - Touch targets are generally 48dp+ (compliant)
  - High contrast on primary CTAs (white on orange)
  - Semantic HTML structure (h1, h2, section, nav, header)
  - aria-labels on key buttons ("Go back", "Capture Photo", "Close details")
  - Font sizes mostly ≥ 14px for body text

  ⚠️ NEEDS ATTENTION:
  - 10px label text (tracking-widest labels) — may be too small (< 12px)
  - Low contrast: text at 60% opacity (e.g., white/60) fails AA
  - Some decorative images lack descriptive alt text
  - Toggle switches rely solely on color (no text label for state)
  - No visible focus indicators defined (keyboard navigation)

  ❌ MISSING:
  - No high-contrast mode toggle
  - No text-size adjustment option
  - No focus-visible styles for keyboard users
  - Screen reader: some interactive elements lack ARIA roles
  - Color-coded map markers need non-color differentiation
    (colorblind users can't distinguish green/dark/white)

1. PROJECT OVERVIEW & VISION
================================================================================

PURPOSE:
Oil Watcher is a community-powered Android application that enables users to
report and discover real-time fuel prices at gas stations. The app leverages
on-device machine learning (Google ML Kit) to extract prices from photos of
gas station price boards, eliminating the need for manual data entry.

VISION:
"Crowdsourced gas prices, powered by your camera."

Users simply snap a photo of a gas station's price sign. The ML model running
locally on their device reads the prices, the user confirms them, and the data
is instantly available to the entire community on an interactive map.

VALUE PROPOSITION:
  • For Contributors: Earn points, climb leaderboards, unlock "Pro Status"
  • For Consumers: Find the cheapest gas nearby before driving there
  • For the Community: Collectively save money through shared price intelligence

DIFFERENTIATORS:
  • On-device OCR — no cloud dependency for scanning, fast & private
  • One-tap contribution — photo → extract → confirm → done
  • Gamification keeps the data fresh through sustained community engagement
  • Premium editorial UI design (not generic material look)

5. TECHNOLOGY STACK & JUSTIFICATION
================================================================================

ANDROID APP:
────────────
  Language:        Kotlin 2.0+
  Min SDK:         26 (Android 8.0, covers 95%+ of devices)
  Target SDK:      35 (Android 15)
  UI Framework:    Jetpack Compose with Material 3
  Camera:          CameraX (1.4.x)
  ML/OCR:          Google ML Kit Text Recognition v2 (on-device)
  Maps:            Google Maps SDK for Android + Maps Compose
  Navigation:      Jetpack Navigation Compose (type-safe)
  DI:              Hilt (Dagger-based)
  Networking:      Retrofit + OkHttp (for any REST APIs)
  Image Loading:   Coil for Compose
  Local Storage:   Room + DataStore (preferences)
  Async:           Kotlin Coroutines + Flow
  Build:           Gradle with Version Catalogs

WHY THESE CHOICES:
  • Jetpack Compose: The UI mockups use Material Design 3 tokens directly.
    Compose's M3 theme system maps 1:1 to the design tokens in DESIGN.md.
  • CameraX: Simplifies camera lifecycle, integrates directly with ML Kit's
    ImageAnalysis use case. No need for deprecated Camera2 boilerplate.
  • ML Kit (on-device): The bundled model is ~4MB. Processes frames in <100ms.
    No network call. No privacy concern. No cost per API call. Perfect for
    the "just click the camera" UX.
  • Google Maps: The mockups clearly show a map-centric home screen. Maps SDK
    supports custom markers, clustering, and styling out of the box.

BACKEND (FIREBASE):
───────────────────
  Authentication:  Firebase Auth (Google Sign-In + Email/Password)
  Database:        Cloud Firestore (real-time sync, offline caching)
  File Storage:    Cloud Storage for Firebase (price board photos)
  Serverless:      Cloud Functions (points calc, leaderboard aggregation)
  Messaging:       Firebase Cloud Messaging (push notifications)
  Analytics:       Firebase Analytics + Crashlytics

WHY FIREBASE:
  • Real-time updates: When a user submits a price, it appears on everyone's
    map immediately via Firestore listeners.
  • Offline-first: Firestore has built-in offline persistence. Users can browse
    cached prices without internet.
  • Serverless: No backend server to deploy/maintain. Cloud Functions handle
    business logic (points, validation) on triggers.
  • Scales automatically with user base.

6. ML KIT OCR — DETAILED INTEGRATION PLAN
================================================================================

OVERVIEW:
─────────
Google ML Kit Text Recognition v2 runs entirely on the device. The model ships
bundled with the APK (~4MB additional size). It can process images in ~50-100ms
on modern phones.

DEPENDENCY:
───────────
  implementation("com.google.mlkit:text-recognition:16.0.1")

PIPELINE:
─────────

  Step 1: CAPTURE
  ───────────────
  CameraX ImageCapture use case captures a high-resolution JPEG.
  Alternative: ImageAnalysis for real-time preview scanning.

  Step 2: CONVERT
  ───────────────
  val inputImage = InputImage.fromFilePath(context, imageUri)
  // or
  val inputImage = InputImage.fromMediaImage(mediaImage, rotationDegrees)

  Step 3: RECOGNIZE
  ─────────────────
  val recognizer = TextRecognition.getClient(TextRecognizerOptions.DEFAULT_OPTIONS)
  recognizer.process(inputImage)
      .addOnSuccessListener { text -> extractPrices(text) }
      .addOnFailureListener { e -> handleError(e) }

  Step 4: EXTRACT PRICES
  ──────────────────────
  fun extractPrices(text: Text): List<FuelPrice> {
      val priceRegex = Regex("""\$?\d{1,2}\.\d{2}""")
      val prices = mutableListOf<PriceCandidate>()

      for (block in text.textBlocks) {
          for (line in block.lines) {
              val match = priceRegex.find(line.text)
              if (match != null) {
                  prices.add(PriceCandidate(
                      value = match.value.removePrefix("$").toDouble(),
                      boundingBox = line.boundingBox,
                      confidence = line.confidence ?: 0f,
                      rawText = line.text
                  ))
              }
          }
      }

      // Sort by vertical position (top to bottom on price board)
      prices.sortBy { it.boundingBox?.top ?: 0 }

      // Map to fuel grades based on position
      return mapToFuelGrades(prices)
  }

  Step 5: MAP TO FUEL GRADES
  ──────────────────────────
  Gas station price boards typically display prices top-to-bottom:
    Position 1 (top)    → Regular (87 octane)
    Position 2          → Midgrade (89 octane)  — sometimes absent
    Position 3          → Premium (91/93 octane)
    Position 4 (bottom) → Diesel

  Additionally, look for label keywords near the price:
    "REGULAR", "REG", "UNLEADED" → Regular
    "MID", "PLUS", "MIDGRADE"    → Midgrade
    "PREMIUM", "PREM", "SUPER"   → Premium
    "DIESEL"                      → Diesel

  Step 6: CONFIDENCE SCORING
  ──────────────────────────
  - ML Kit confidence > 0.8 → "Detected" (show green badge)
  - ML Kit confidence 0.5-0.8 → "Low Confidence" (show yellow, user should verify)
  - ML Kit confidence < 0.5 → Don't pre-fill, mark as "Optional"
  - No detection → Empty field, user enters manually

EDGE CASES & HANDLING:
──────────────────────
  • LED price boards at night  → ML Kit handles well with high contrast
  • Sun glare / reflections    → Prompt user to retake or adjust angle
  • Partially visible prices   → Extract what's visible, leave rest blank
  • Non-standard formats       → Some stations use X.XX9 (9/10ths); strip trailing digit
  • Multiple boards in frame   → Use the largest/most centered text block
  • Blurry photos             → Check image sharpness before OCR, prompt retake

15. SECURITY & PRIVACY CONSIDERATIONS
================================================================================

  DATA PRIVACY:
  • OCR runs entirely on-device — no images sent for text extraction
  • Uploaded photos stored in Firebase Storage with security rules
  • User location data used only for nearest-station detection
  • Users can delete their data and account

  AUTHENTICATION:
  • Firebase Auth handles secure token management
  • Google Sign-In for trusted identity
  • Optional email/password with email verification

  FIRESTORE SECURITY RULES:
  • Users can only write their own contributions
  • Users can only read/write their own profile
  • Station prices readable by all authenticated users
  • Leaderboard data is read-only (aggregated by Cloud Functions)

  RATE LIMITING:
  • Cloud Functions enforce max submissions per user per hour
  • Prevents spam/abuse of the points system
